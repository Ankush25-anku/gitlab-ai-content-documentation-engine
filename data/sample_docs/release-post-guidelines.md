# Release post guidelines

Each release post entry describes one change and links to its documentation.

## Entry structure

Start with the benefit to the user. Then describe what changed, who it affects and how to start using it. Name the tier (Free, Premium, Ultimate) and the offerings (GitLab.com, GitLab Self-Managed, GitLab Dedicated).

## Deprecations and breaking changes

List deprecations and breaking changes in their own entries. State the milestone in which the feature is removed and the migration path.
